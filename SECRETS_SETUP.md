# Local secrets setup (not tracked in git)

These files/folders are required to build and manufacture devices but are
intentionally excluded from git (see `.gitignore`). Recreate them locally
after cloning:

## 1. `secrets/firebase-service-account.json`
Firebase Admin SDK service account key (JSON) with permission to manage
Firebase Auth users for this project. Generate from:
Firebase Console -> Project Settings -> Service Accounts -> Generate new
private key.

## 2. `scripts/devices.json`
Per-device registry (Firebase auth credentials, chip IDs, customer info).
Copy `scripts/devices.example.json` to `scripts/devices.json` and fill in
real values, or let `build_device.py` create/populate entries automatically
on first build for a new device (it generates a random Firebase password
per device if one isn't present).

## 3. `generated/device_config.generated.h`
Auto-generated by `scripts/build_device.py` on every build. Never hand-edit
or commit this file.

## 4. `customers/devices.json`
Customer-facing device registry (may contain PII). Recreate/sync locally as
needed; do not commit.

---
If you ever suspect one of these has been committed, shared, or otherwise
exposed: rotate the Firebase service account key immediately (zero device
impact - it's never used on-device). For a device's own Firebase Auth
password, **do not** just clear `firebasePassword` and rebuild on a device
that's already deployed - that pushes the new password to Firebase Auth
immediately, before the device has any way to know about it, and locks the
device out (it can't even receive an OTA command afterward, since OTA
delivery itself depends on being logged into Firebase).

## Rotating a deployed device's password safely

Use the two-phase rotation commands instead, which build/stage the new
firmware *before* Firebase Auth ever changes:

```bash
# Phase 1: generates a new password, builds+stages firmware with it,
# but does NOT touch Firebase Auth. The device keeps working normally
# on its existing password the whole time.
python build_device.py rotate-start <deviceId>

# -> now push the OTA update to that device as usual, and CONFIRM it
#    actually rebooted onto the new build (new fwVersion in Firebase,
#    or "Firebase token ready." in the serial monitor after reboot)

# Phase 2: only after that's confirmed, this pushes the new password
# live to Firebase Auth (matching what the device is already running).
python build_device.py rotate-finalize <deviceId>
```

If you staged a rotation but change your mind before finalizing:
```bash
python build_device.py rotate-abort <deviceId>
```
This discards the staged password; Firebase Auth and the currently-deployed
firmware are untouched either way.

Never run `rotate-finalize` until you've actually confirmed the device is
running the staged build - finalizing early is exactly what causes a
lockout.
